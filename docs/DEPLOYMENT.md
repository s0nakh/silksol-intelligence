# Развёртывание в QazCloud

SilkSol Intelligence поставляется как один Docker-контейнер (дашборд + REST API, Node.js 22,
без внешних runtime-зависимостей). Данные и вычисления остаются в контуре заказчика в Казахстане.

## Быстрый старт на виртуальной машине

```bash
git clone https://github.com/s0nakh/silksol-intelligence.git && cd silksol-intelligence
cp .env.example .env            # заполнить SILKSOL_API_KEYS, при необходимости пароль дашборда
docker compose up -d --build    # http://<vm>:3000, API: http://<vm>:3000/api/v1
curl -s localhost:3000/api/v1/health
```

Без Docker: `npm ci && npm run build:node && npm start`.

## Целевая схема для пилота

```text
 Пользователи (браузер)        ERP / 1С / TMS партнёра          Страховщик / банк (API)
          │                              │                               │
          └──────────────┬───────────────┴───────────────┬───────────────┘
                         ▼                               ▼
              ┌─────────────────────────────────────────────────────┐
              │  QazCloud: балансировщик + TLS + WAF                │
              │  SSO (OIDC: IdP заказчика / Keycloak), rate limit   │
              └─────────────────────────┬───────────────────────────┘
                                        ▼
              ┌─────────────────────────────────────────────────────┐
              │  silksol-intelligence (контейнер, 2+ реплики)       │
              │  дашборд · REST API v1 · модели риска               │
              └───────┬───────────────────────────────┬─────────────┘
                      ▼                               ▼
         PostgreSQL (журналы аудита,        Объектное хранилище (отчёты,
         отчёты, события простоя)           выгрузки, датасеты для обучения)
                      ▲
                      │  ETL: события ж/д и портов (CMR/СМГС, gate-in/out), AIS, Казгидромет
```

- **Где выполняется:** Kubernetes или ВМ QazCloud. GPU не обязателен для инференса; GPU-ресурсы
  нужны для обучения моделей простоя (CatBoost / survival) на исторических данных пилота.
- **Хранение данных в РК:** все базы и бэкапы размещаются в ЦОД QazCloud. Персональные данные
  (ФИО водителей, контакты экспедиторов) хранятся только там.
- **Сеть:** наружу контейнеру нужен только доступ к источникам данных (метеоданные, AIS);
  при работе в закрытом контуре они поступают через ETL-шлюз заказчика.

## Конфигурация

| Переменная                                             | Назначение                                 |
| ------------------------------------------------------ | ------------------------------------------ |
| `PORT`, `HOST`                                         | Порт / адрес (по умолчанию 3000 / 0.0.0.0) |
| `SILKSOL_API_KEYS`                                     | Ключи API: `клиент:секрет` через запятую   |
| `SILKSOL_DASHBOARD_USER`, `SILKSOL_DASHBOARD_PASSWORD` | Basic-auth дашборда (до подключения SSO)   |
| `SILKSOL_WEATHER_MODE`                                 | `live` — живая погода, `mock` — сценарий   |
| `SILKSOL_AIS_MODE`, `SILKSOL_AIS_API_URL`              | Живой AIS через прокси провайдера          |

## Безопасность контейнера

- Запуск от непривилегированного пользователя `node`, файловая система только для чтения,
  `no-new-privileges` (см. `docker-compose.yml`).
- Встроенный healthcheck `GET /api/v1/health`.
- Секреты только через переменные окружения / секрет-хранилище, не в образе и не в git.
- Журнал доступа к API — JSON в stdout для SIEM заказчика.

## Что нужно от пилотного партнёра

1. ВМ или namespace в QazCloud, доступ к IdP для SSO.
2. Выгрузка событий простоя за 1–2 года (прибытие / убытие по узлам, СМГС/CMR) для обучения модели.
3. Журнал закрытий портов (капитан порта) — заменит погодную прокси-метку в бэктесте.
4. Контакт по ИБ для согласования требований (см. `docs/COMPLIANCE.md`).
