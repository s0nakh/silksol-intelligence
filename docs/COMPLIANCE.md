# Комплаенс: законодательство РК и корпоративная среда

Документ описывает, как продукт соотносится с требованиями, которые применимы к пилоту в
казахстанской корпоративной среде. Это позиция команды, а не юридическое заключение.
Перед коммерческим запуском её проверяет юрист.

## Что продукт делает и чего не делает

- **Делает:** аналитика и поддержка решений: вероятность задержки груза, прогноз ETA,
  контроль SLA по простоям, вероятность закрытия портов, проверяемые отчёты о задержке.
- **Не делает:** не страхует, не принимает платежи, не хранит деньги, не выпускает токены,
  не принимает юридически значимых решений. Итоговое решение всегда за человеком.

## Персональные данные

- Ядро продукта работает с неперсональными данными: погода, позиции судов (AIS), события грузов.
- Персональные данные появляются при интеграции: ФИО водителей и контакты в CMR/СМГС, учётные
  записи пользователей. Для них:
  - хранение только в базах на территории РК (ЦОД QazCloud), включая бэкапы;
  - минимизация: в модели не передаются ФИО, только обезличенные идентификаторы рейсов;
  - доступ по ролям через SSO заказчика, журналирование доступа;
  - сроки хранения и порядок удаления фиксируются в договоре с пилотным партнёром.

## Информационная безопасность корпоративного заказчика

Ориентир — Единые требования в области ИКТ и обеспечения ИБ и внутренние политики заказчика.

- Развёртывание в контуре заказчика / QazCloud, без зависимости от зарубежных облаков.
- TLS на балансировщике, SSO (OIDC), ключи API по клиентам, секреты вне кода.
- Контейнер без root, файловая система только для чтения, healthcheck.
- JSON-журналы для SIEM; целостность журнала событий груза проверяется хешами.
- Зависимости фиксируются lock-файлом; сканирование уязвимостей образа — в CI пилота.
